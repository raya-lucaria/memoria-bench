01 / Foundations

What Exactly Is an LLM Harness?

Think of an LLM as a brilliant consultant sitting in an empty room with no computer, no clock, and no notepad. Every few seconds, you hand them a paper question, and they write back an answer. Once the note is passed, they forget who you are.

A harness gives that consultant a desk, a terminal, access to your code repository, persistent notebooks, and an automated assistant to run their tests. It transforms a one-shot chatbot into an autonomous engineer.

🎯

Context & Attention Control

LLMs get overwhelmed when prompt history gets too long. A good harness compresses old turns, keeps system instructions concise, and ensures critical guidelines never fall out of attention.

🛠️

Tools & Interfaces

Bridges thoughts to action. Whether through raw terminal commands, precise file search-and-replace, or protocols like MCP (Model Context Protocol), the harness converts JSON tool calls into real effects.

🛡️

Safe Execution Sandbox

Agents run experimental code. A harness isolates that execution inside Docker containers, sub-shells, or virtual environments so your host machine stays completely safe from destructive commands.

🔄

Self-Correction Loops

When a command fails or a test turns red, the harness feeds the exact error back to the model, giving it the autonomy to diagnose, rewrite, and verify its work until it succeeds.

02 / Deep Dive

How the 4 Harnesses Work

Minimalist Daily Coding Agent

Pi (pi-mono / pi-coding-agent)

Created by Mario Zechner · Written in TypeScript / Node.js

The Philosophy in Plain English

Most modern AI coding assistants have become heavy, bloated software suites filled with popups, hidden background prompts, and complex plan modes that eat up your token quota. Pi strips all of that away. Its philosophy is simple: modern frontier LLMs already know how to write code—give them four fast, rock-solid tools, keep the system prompt under 1,000 tokens, and stay out of the developer's way.

Key Characteristics
  • Only 4 Fundamental Tools: The core harness ships with just read, write, edit, and bash. That's everything an engineer needs.
  • Sub-1,000 Token Prompt: Protects your context window and ensures the model dedicates its token budget to your code rather than long preamble instructions.
  • Navigable Tree Sessions: Conversations are saved as branching trees, making it easy to rewind, branch, or test different solutions.
  • Extensible Without Bloat: If you want MCP support, custom themes, or new workflows, you add small, typed TypeScript extensions that hot-reload immediately.
Architecture Flow
Developer in Terminal
  └─> Compact Prompt (< 1,000 tokens)
        └─> Unified LLM Layer (pi-ai)
              └─> 4 Clean Tools: read | write | edit | bash
                    └─> Git Repo / Branching Session Tree
General-Purpose Autonomous Agent & Gateway

Hermes (NousResearch/hermes-agent)

Created by Nous Research · Python, SQLite & s6-overlay Docker

The Philosophy in Plain English

Hermes is built for autonomous execution across environments. It is not just a chat CLI: it is a full background service (gateway) that can connect to chat platforms (Discord, Telegram, Slack), execute browser automation via headless Chromium, coordinate subagents, and expose standard OpenAI-compatible endpoints so other apps can command it. Paired with Hermes Bench, it judges AI success by verifying the actual files and state left on disk rather than pleasant conversational replies.

Key Characteristics
  • Supervised Docker Daemon: Runs under s6-overlay with automatic process supervision, background cron scheduling, and persistent volume storage.
  • Built-in Toolsets & Skills: Ships with 40+ bundled skills (code inspection, browser automation, systematic debugging, data analysis) and native MCP support.
  • OpenAI-Compatible API Gateway: Exposes /v1/chat/completions on port 8642, enabling local and remote apps to invoke it directly.
  • State-Based Verification: Hermes Bench grades whether problems were solved by inspecting real workspace artifacts and exit codes.
Architecture Flow
Gateway Clients (Web / CLI / Bots)
  └─> Hermes Agent Core + Skills System
        └─> Tool Manager (Browser, Bash, MCP, Files)
              └─> Sandboxed Execution Environment
                    └─> Hermes Bench / Filesystem State Audit
Automated Software Benchmarking Harness

SWE-bench Harness (swebench.harness)

Created by Princeton NLP · Python & Multi-Container Docker

The Philosophy in Plain English

Unlike Pi or Hermes, SWE-bench is not an interactive assistant you talk to. It is the gold-standard grading harness used across AI research to test whether an LLM can resolve real-world software bugs. It takes a problem description from a historical GitHub issue, feeds it to the model, and then rigorously grades the resulting code patch against hidden unit tests inside a replica Docker environment.

Key Characteristics
  • Deterministic Replicas: Pre-built Docker images recreate the exact historical commit, Conda environment, and dependencies for hundreds of real open-source Python repos.
  • Dual-Patch Grading: Applies the model's git diff (model_patch) and then injects the human maintainer's hidden test patch (test_patch).
  • Binary Ground-Truth: An instance passes only if all FAIL_TO_PASS tests succeed (the bug was fixed) and all PASS_TO_PASS tests pass (no regressions were introduced).
  • Concurrency & Caching: Runs dozens of benchmark instances concurrently across isolated worker containers.
Architecture Flow
Model's Proposed Git Patch
  └─> SWE-bench Harness Loader
        └─> Exact Historical Docker Container
              ├─> Apply Code Patch + Hidden Test Patch
              └─> Run pytest / unittest
                    └─> Pass/Fail Verdict (No Regressions)
Recursive Reasoning & Compute Scaling

PrimeAgent (prime-agent)

Created by Prime Intellect · Built on Pi TUI + Stateful IPython REPL

The Philosophy in Plain English

When humans tackle difficult math, science, or algorithmic problems, we don't just write out the final answer in one go—we write draft code, inspect intermediate values, run simulations, and refine our approach. PrimeAgent is an open-source Recursive Language Model (RLM) harness that gives models this exact capability by connecting them to a persistent, stateful Python REPL and daemon subagents.

Key Characteristics
  • Persistent IPython REPL: Unlike stateless one-shot terminal calls, variables, functions, and datasets remain active in memory from one step to the next.
  • Test-Time Compute Scaling: Models can run hundreds of algorithmic hypothesis checks before delivering the final answer, dramatically increasing problem-solving capability.
  • Continual Memory: Tracks historical errors and curates reusable skills across complex, multi-stage workflows.
  • Subagent Delegation: Spawns parallel background workers to explore alternative algorithmic branches simultaneously.
Architecture Flow
Complex Algorithmic Goal
  └─> Recursive Language Model (RLM) Loop
        ├─> Stateful IPython REPL (Variables & State Persist)
        ├─> Continual Skill & Error Memory
        └─> Parallel Daemon Subagents
              └─> Verified Breakthrough Output

04 / Architectures

Tipos de Memoria en Agentes: Secciones Especializadas

Cada arquitectura aborda la memoria persistente bajo un prisma y compromiso distinto. A continuación se desglosan en secciones independientes los 4 modelos principales de memoria para agentes de código.

Tipo 1: Curated File & Lexical Hermes Agent · OptMem · AGENTS.md

1. Memoria Basada en Archivos Curados y Búsqueda Léxica

Filosofía: Cero llamadas a APIs de LLM al guardar, máxima estabilidad en la caché de prompts (prompt caching) y control absoluto por parte del desarrollador. En lugar de procesar los mensajes con un modelo para resumirlos, se guarda directamente en archivos planos o registros append-only.

📄
Archivos Estructurados Nativos (Hermes):

Inyección controlada de MEMORY.md (hechos y preferencias) y USER.md con un presupuesto estricto de caracteres (~1000 tokens) para que el prompt base permanezca siempre en la caché del proveedor.

⚡
OptMem (Plugin Append-Only & BM25):

Implementación minimalista (rarf/optmem-hermes-plugin). Registra eventos secuenciales y los recupera con regex y BM25 sin depender de bases de datos vectoriales pesadas ni embeddings externos.

🔍
Auditoría Transparente:

Cualquier desarrollador puede abrir el archivo de memoria con cat o VS Code y editar o borrar lo que el agente "cree saber".

Ficha Técnica
Sobrecarga en Escritura: 0 tokens (I/O directo)
Costo en Boot / Prompt: ~400 - 1,000 tokens fijos
Algoritmo de Búsqueda: BM25 / Regex exacto
Dependencias: Cero (Python puro / SQLite)
Ideal Para: Desarrollo local rápido, CLI
Tipo 2: Spatial "Second Brain" MemPalace · Method of Loci · MCP

2. Memoria Espacial "Second Brain" (MemPalace)

Filosofía: Almacenamiento 100% literal (verbatim). El resumen tradicional destruye información crítica: los "porqués" de una decisión técnica, los trade-offs descartados y el contexto de errores en el código. MemPalace estructura la memoria en una jerarquía espacial basada en el palacio de la memoria mnemotécnico.

WING (Dominio o Proyecto)
Repositorio / Proyecto (ej. auth-microservice)
HALL (Área temática)
Criptografía & Tokens
DRAWER (Decisiones Literales)

"Migrado de RSA a Ed25519 el 12/08: los headers JWT superaban el límite de 8KB en el proxy Ingress."

HALL (Área temática)
Persistencia & Pools
DRAWER (Decisiones Literales)

"No usar transacciones anidadas en billing_worker por deadlocks en PostgreSQL."

Rendimiento en Benchmarks y Debate: Alcanzó 96.6% Recall@5 en LongMemEval sin invocar LLMs al guardar. Si bien las afirmaciones de 100% de recall con reranking causaron debate por sobre-ajuste a ciertos conjuntos de prueba, los análisis independientes validan que el filtrado espacial con embeddings locales supera con creces a la extracción por resúmenes.
Ficha Técnica
Sobrecarga en Escritura: 0 llamadas LLM (embeddings locales)
Costo en Boot / Prompt: ~170 tokens base (punteros)
Estructura: Wings → Halls → Drawers
Motor Vectorial: ChromaDB local
Integración: MCP (Model Context Protocol)
Ideal Para: Second Brain personal, contexto multi-sesión
Tipo 3: Working Memory & Code Graphs AST Graphs · CrossCode · Repo Context

3. Memoria Estructural y de Trabajo para Código (AST / Dependency Graphs)

Filosofía: Un repositorio no es texto plano; es una red densa de tipos, herencias, llamadas a funciones y referencias cruzadas entre ficheros. Esta memoria mantiene activo un grafo estructural para que el agente recuerde dónde se definen interfaces y clases en otras partes del monorepo.

🕸️
Grafos de Dependencias & AST:

Indexa clases, firmas de métodos y módulos importados. Permite responder consultas como "¿qué archivos llaman a `verifySession` y cómo esperan el error?" sin tener que leer cada archivo línea por línea.

🔄
Working State (REPL / Kernel Interactivo):

Memoria en tiempo de ejecución (como el kernel IPython en PrimeAgent) donde las variables, los DataFrames y los resultados de compilación se mantienen vivos entre pasos de ejecución.

Ficha Técnica
Estructura de Datos: Tree-sitter / Grafo de Símbolos
Actualización: En cada guardado / git diff
Resolución: Definición → Referencia cruzada
Evaluado en: RepoBench, CrossCodeEval, LongMemCode
Tipo 4: Managed Cloud & Knowledge Extraction Mem0 · Zep · Letta / MemGPT

4. Memoria Gestionada con Extracción Semántica y Grafo de Entidades

Filosofía: Un modelo LLM en segundo plano analiza constantemente las interacciones, extrae entidades ("el usuario prefiere async/await en TypeScript"), detecta contradicciones temporales y las sincroniza en una nube centralizada accesible por múltiples clientes o interfaces.

🧠
Extracción Automática de Hechos:

Crea un perfil evolutivo del desarrollador y del proyecto. Resuelve contradicciones cuando una directiva anula a otra anterior.

☁️
Sincronización Multi-Dispositivo:

Permite que el mismo historial y contexto persistan si el usuario interactúa desde VS Code, el terminal CLI o un bot de Telegram/Slack.

Ficha Técnica
Sobrecarga en Escritura: Alta (Llamada LLM en cada mensaje)
Latencia de Escritura: 300ms - 1500ms
Backend: Neo4j, PostgreSQL (pgvector), Zep Server
Evaluado en: LoCoMo, LongMemEval

05 / Evaluaciones Rigurosas

Benchmarks Relevantes: Código, Navegación y Memoria

Para saber si una memoria o un arnés realmente funcionan en ingeniería de software, se necesitan suites que midan desde la recuperación precisa de funciones hasta la resolución de incidencias en repositorios de miles de archivos.

Catálogo de Benchmarks Especializados

Código + Memoria Determinista Monorepos (Go, Rust, Py)
LongMemCode

Benchmark determinista creado expresamente para evaluar los sistemas de memoria y recuperación de agentes de código (Cursor, Claude Code, Cline, Aider) sin jueces LLM.

Qué Evalúa: Precisión de recuperación en repos gigantes como Kubernetes (2000+ ficheros)
Métricas: Latencia de consulta (ms), Coste en tokens y Exactitud de Contexto
Protocolo: Adaptadores mediante JSON sobre stdio
Needle in a Haystack Semántico Multi-lenguaje
RepoQA (Searching Needle Function)

Mide la capacidad de encontrar la función exacta en un repositorio masivo mediante descripciones en lenguaje natural sin revelar el nombre ni palabras clave de la función.

Qué Evalúa: Comprensión semántica de código en contextos largos
Lenguajes: Python, Java, TypeScript, C++, Rust
Importancia: Verifica si la memoria localiza la lógica correcta o solo hace grep ciego
Estándar de Oro en Software GitHub Issues Reales
SWE-bench (Lite, Verified & Multimodal)

Evalúa la capacidad de un agente autónomo para resolver incidencias reales de GitHub: explorar el repositorio, localizar el bug, generar el parche y pasar la suite de pruebas unitarias.

Memoria Requerida: Exploración y navegación en miles de archivos
Métricas: Tasa de resolución (% de tests unitarios que pasan)
Variantes: Verified (humano auditado), Multimodal (gráficos/UI), Multilingual
Estructura Multi-Archivo Cross-File Context
RepoBench & CrossCodeEval

Evalúan la memoria estructural entre archivos: cómo el modelo autocompleta y genera código que depende de clases, tipos y funciones declaradas en otros ficheros del proyecto.

Foco de Memoria: Referencias cruzadas entre límites de archivos
Métricas: Code Match, Identifier Recall, Retrieval Hit Rate
Relevancia: Evita alucinaciones de métodos o imports inexistentes
Second Brain & Trajectory Hasta 100M+ tokens
LongMemEval & LongMemEval-V2

Evalúa la consistencia temporal, actualización de creencias y manejo de información obsoleta. La versión V2 incorpora trazas y trayectorias reales de agentes web y de código.

Sistemas Evaluados: MemPalace (96.6% Recall@5), Mem0, Zep, Letta
Métricas: Recall@K, Invalidación de hechos caducados
Escala: Pájaros en pajares masivos multi-sesión
Trazas & Verificación Cientos de Sesiones
LoCoMo & PAST-Bench

LoCoMo evalúa razonamiento multi-salto sobre cientos de sesiones. PAST-Bench audita si el agente realmente ejecutó el bucle de herramientas (write/retrieve) o si solo alucinó con pesos paramétricos.

Métricas: MRR, Hit Rate, Fidelidad de traza de ejecución
Harness Target: Hermes Agent, OptMem, ReAct frameworks
Prevención: Detección de falsos positivos en memorias de agentes

05.5 / Metodología Académica

Plan de Pruebas: Memoria Agnóstica con Modelos 100% Locales (Sin API Key)

Diseño experimental bajo el constraint de Memoria Agnóstica: cero costo de tokens, cero suscripciones y total desacoplamiento entre el modelo, el arnés y el formato de almacenamiento de memoria.

Constraint: 0$ Cost / CPU Local

1. Desacoplamiento de Modelo (Model-Agnostic)

La memoria no depende de llamadas propietarias (ej. OpenAI Function Calling). Funciona sobre modelos abiertos estándar vía Ollama / llama.cpp (Qwen2.5-Coder, Llama-3.2).

2. Desacoplamiento de Arnés (Harness-Agnostic)

La misma base de conocimiento puede ser leída y modificada por Hermes, MemPalace, Letta o Mem0 a través de una interfaz estandarizada (JSONL / Markdown / SQLite local).

3. Cero Costo y Privacidad Total (Zero API-Key)

Tanto la inferencia del agente como la extracción semántica y los embeddings se ejecutan localmente en CPU/RAM (<14GB RAM) usando fastembed y cuantizaciones GGUF q4_k_m.

Protocolo de Pruebas en 4 Fases (Reproducible para el Laboratorio)

Fase 1: Preparación del Entorno Setup 100% Local

Instalación de servidor Ollama local con modelos cuantizados (3B y 7B) y biblioteca FastEmbed para embeddings ligeros en CPU sin dependencias externas.

Fase 2: Benchmarks de Código LongMemCode & RepoQA

Inyección de 20 funciones "needle" en un repositorio de prueba. Medición de tasa de acierto (Top-1 Recall) y tiempo de respuesta sin juez comercial.

Fase 3: Persistencia Temporal LoCoMo & Multisesión

Prueba de 20 sesiones simuladas donde se definen reglas de arquitectura en la sesión 1 y se audita su cumplimiento estricto en la sesión 20.

Fase 4: Test de Portabilidad Transfer Test Agnóstico

Generar la memoria en un arnés (ej. MemPalace) y transferir el almacenamiento a otro arnés (ej. Hermes) sin reindexar, validando el desacople total.

# 3. Ejecutar suite de pruebas de memoria agnóstica

06 / Sinergia Total

Cómo Encajan Todos los Arneses y Memorias

1. Pi as the Minimalist Foundation

By proving that four basic tools and a small system prompt are all a strong model needs, Pi serves as an ideal baseline and inspiration for other frameworks (including being the UI foundation for PrimeAgent).

2. Hermes as the Versatile Operator

Hermes proves that when an agent needs broad real-world utility—like orchestrating browser tools, running background schedules, or coordinating subagents—a structured gateway harness is essential.

3. SWE-bench as the Truth Arbiter

Without a standardized evaluation harness like SWE-bench, measuring whether an agent is truly improving or just hallucinating would be impossible. It provides the objective finish line.

4. PrimeAgent as the Reasoning Frontier

PrimeAgent shows that the harness itself can provide reasoning compute. By granting persistent execution state, it pushes open-weights models to solve problems once thought to require human research mathematicians.

5. MemPalace & OptMem as the Persistent Second Brain

An agent without long-term memory is forced to re-learn user preferences, architectural rules, and project decisions from scratch in every session. By coupling spatial hierarchy (MemPalace) or lightweight append-only logs (OptMem) to the harness, agents evolve into continuous personal collaborators.
