Memoria de agentes: números para decidir

Corte: 17-nov-2026 · Pregunta: ¿memoria unificada entre proyectos o memorias por proyecto? · scouting de DabtcAvila para memoria-bench
Lectura de los números: hoy no hay evidencia para unificar. En la máquina medida, 7.7 % de las sesiones leyó memoria de otro proyecto y un índice unificado pesaría 6.4 veces el tope que carga Claude Code. Con modelos vigentes: Claude Code sobre archivos con Opus 5.5 acierta 97 % contra 95 % de Mem0 (MemoryTax, oct-2026); en tareas de código encadenadas, sin memoria 38.5 %, Mem0 39.6 %, historial completo 40.6 % (CoReMem, nov-2026); y en la prueba de Anthropic del 6-nov una página compartida conservó 41 de 57 datos contra 57 de 57 con una página por contrato. El dato en contra: el mismo estudio de Anthropic muestra que búsqueda más una wiki consolidada sube de 53 a 61 % de criterios cumplidos. El proyecto foco tiene solo 4 sesiones: muestra insuficiente.

Uso real medido en una máquina

Un solo usuario; los nombres de proyecto están anonimizados. Fuente: transcripciones de Claude Code del 15-oct al 17-nov-2026. 183 sesiones, 45,235 llamadas a herramientas, 37 carpetas de memoria. Solo lectura. Se repite con python3 medir.py salida.json.

Los umbrales son propuesta mía, ajustables. «Unificar» se justifica si se cumplen al menos tres.
