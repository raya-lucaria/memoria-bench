Research brief · November 2026

Agent Memory Field Guide

How coding-agent harnesses remember things between sessions: the native memory in Claude Code and Gemini CLI, the "second brain" pattern, OptMem, MemPalace, and the memory providers in Hermes Agent. Covers benchmark claims, independent reruns, and what users report after using them.

Compiled 2026-11-17 from web search. Reddit threads were not directly indexable, so Reddit opinions are quoted second-hand through the articles that cite them. Benchmark pilot run on 2026-11-18 on one laptop, with subscriptions and free tiers only.

The short answer

  • Use
    Claude Code native memory (CLAUDE.md + auto memory) as your base. It's free, plain Markdown you can audit, and already on.
  • Add if needed
    OptMem when you want one memory shared by Claude Code, Gemini, Codex and Hermes. Expect regex search, not semantic search.
  • Add if needed
    Hindsight as the Hermes provider: open source, self-hostable, and the strongest judged-accuracy numbers. Honcho second, if you want user modeling.
  • Different job
    Second brain (Obsidian) is a knowledge base for you that the agent can read. It works only if you keep it pruned.
  • Be skeptical
    MemPalace and Mem0 headline scores. Both fall apart once you check the metric or rerun the system independently.
  • Measure
    LongMemEval-S is the benchmark to run yourself. In our 30-question pilot, a free local embedder found the evidence almost every time, and the answering model made the difference: Sonnet kept 87 % with retrieved memory, Haiku fell to 70 %.

How to read memory benchmarks

Almost every vendor claims 90 %+ on the same two benchmarks. The numbers aren't comparable, because each vendor measures something different and picks its own answer model and judge.

LongMemEval

Questions about facts buried in long multi-session chat histories. The most quoted benchmark in 2026.

LoCoMo

Very long conversations with questions about them. Older, and close to saturated: Honcho's no-memory baseline already scores 83.9 %.

Recall@k

Did the right passage appear in the top k results? Measures retrieval only. No answer is generated or graded.

Judge accuracy

An LLM answers using the memory, and another LLM grades the answer. This is the score that matters for agents.

BEAM · MemoryAgentBench

Newer suites that test memory at scale and incremental multi-turn learning. Fewer vendors report them.

Built into the harness

Claude Code

  • CLAUDE.md: your rules. Loaded from the current directory and every parent directory.
  • Auto memory: Claude's own notes in ~/.claude/projects/<project>/memory/, with a MEMORY.md index. On by default since v2.1.59; toggle with /memory.
  • Guides report that only the first ~200 lines of MEMORY.md load at startup, with topic files read on demand. Not confirmed in the official docs.

Hermes Agent providers

  • Built-in Markdown memory always runs, plus one external provider: honcho, hindsight, mem0, supermemory, openviking, holographic, retaindb, byterover (and newer ones).

Part two · Run it yourself

A memory benchmark you can run on a laptop with no API key: what it measures, how it stays fair across harnesses, and what a first 30-question pilot found.

Measuring memory yourself

An agent's memory is used in two steps. First a search picks a few old conversations out of many. Then a model reads them and answers. A good test scores each step on its own, because they fail in different ways. If the search misses the evidence, no model can answer. If the search finds it, a weak reader can still answer badly.

  • Retrieval recall. Did the sessions holding the answer land in the top 5? No model is involved, so it costs nothing and runs locally.
  • Judged accuracy with retrieved memory. The harness answers from those top 5 sessions, and a fixed judge grades the answer.
  • Judged accuracy with the answer sessions given. The harness gets exactly the sessions that hold the answer. This is the ceiling: the score with perfect memory.

The gap between the last two numbers is what memory costs you. The gap between the ceiling and 100 % is the reader's fault, not memory's.

Adapter written but not run here Same for every harness

This is what "agnostic" means here. Each harness is a small adapter that sends one prompt and returns text. Adapters never import each other, so you can add or drop one without touching the rest. The benchmark goes the other way: it owns its data, sample, memory search, prompts and judge, and keeps them identical for every harness. A second benchmark would live in its own folder and share nothing with this one.

The benchmark to use: LongMemEval-S

Use LongMemEval-S, the cleaned release. It's the benchmark every vendor on this page quotes, so your numbers line up against theirs. It ships an official judge prompt for each question type, and it tests five abilities: pulling out a fact, combining facts across sessions, noticing a fact that changed, reasoning about dates, and saying "I don't know" when the answer isn't there. Each question hides its evidence among about 50 chat sessions.

  • Sample: 30 questions, 5 from each of the 6 question types, fixed seed 42. Every harness sees the same 30.
  • Memory: each session is split into turns. BM25 or a local embedder scores the turns, and the top 5 sessions go to the reader.
  • Reader: the LongMemEval answer prompt, with tools, settings and the harness's own memory turned off.
  • Judge: the official LongMemEval judge prompts, copied verbatim, run by one fixed judge (Claude Sonnet through the subscription) for every harness.

One thing it doesn't measure is a harness's own memory files, such as CLAUDE.md, auto memory or GEMINI.md. Those are loaded whole at session start, with no search step to test. Judging them takes a task-based test that runs across real sessions, like MemoryAgentBench, which is a much bigger project.

What the pilot shows

  • Reading is not the bottleneck. Given the right sessions, all three models land between 87 % and 90 %.
  • Search is nearly solved at this size. A free CPU embedder put some evidence in the top 5 for 28 or 29 of 29 questions.
  • The reader decides what memory is worth. With the same retrieved sessions, Sonnet lost one question and Haiku lost six. Only 3 of Haiku's 9 misses lacked evidence in the top 5. Most of the rest are preference questions where Haiku said "I don't know" even though the relevant sessions were in front of it. The reader prompt tells it to say that when unsure, and Haiku takes the instruction more literally.
  • Sonnet's misses are retrieval misses. In 3 of its 4 wrong answers, the top 5 lacked some of the sessions the answer needed. A cross-session question needs every piece, and top 5 sometimes leaves one out.
  • Free tiers are not a test bench. opencode's free models answered about 70 calls this morning, then stopped responding. One model had already been removed from the free list.

Small sample. With 30 questions, every accuracy carries roughly ±11 to ±16 points, so only the Haiku drop is clearly real. The judge is Claude Sonnet, the same family as two of the readers, which may favor them. MiniLM edged out bge-small on recall, but the QA runs used bge-small because it was chosen before the run. One seed, one run each.

The code

Everything is in prueba/memory_bench/, managed with uv. Dependencies are fastembed and rank-bm25, with no torch and no GPU. Each run writes one line per question and resumes where it stopped, so a quota cut-off loses nothing.
